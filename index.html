02 / APPLICATION SECURITY

Security and request lifecycle

Two distinct paths: login/token issuance and subsequent authenticated API requests.

01
React sends login request

Credentials and request metadata reach the Patient API over HTTPS.

02
IP pre-check

Check the requesting IP against blocked-IP records stored in the database.

03
Custom login rate limiter

Login-attempt counters are maintained in local application memory. Requests beyond the configured threshold trigger the blocking policy.

04
Credential validation

Validate the supplied credentials using the application's authentication mechanism.

05
JWT generation

After successful authentication, generate a JWT and return it to the frontend.

Confirmed implementation: blocked IP information is stored in the database; login rate-limit counters are local-memory state.
01
React sends API request

The frontend includes the JWT in the configured request header.

02
Custom JWT filter

A custom Spring Security OncePerRequestFilter extracts and validates the token and establishes the authenticated security context.

03
Authorization

Spring Security evaluates whether the authenticated user is permitted to access the requested resource.

04
Custom sanitization filter

Inspects request data for configured prohibited characters or malicious patterns and rejects suspicious input.

05
Application processing

Accepted requests proceed to the controller, service and repository layers.

Implementation detail to verify: the exact placement of the sanitization filter and rate limiter depends on filter registration. This page reflects the request order you described, not an independently inspected source-code configuration.
